# SE-EDU Git standard

Apply this skill whenever creating, amending, or proposing a commit, and when naming a branch. Use the [SE-EDU Git conventions](https://se-education.org/guides/conventions/git.html) as the authoritative reference.

For commit subjects:

- Write a meaningful imperative subject, preferably within 50 characters and never over 72.
- Capitalize the first letter and do not end the subject with a period.
- Add a concise scope or category prefix only when it improves clarity.

For non-trivial commits, add a body separated by one blank line. Wrap body lines at 72 characters, use paragraphs or bullets as useful, and explain what changed and why. Describe the current situation and rationale in the present tense, then describe the change in the imperative mood; do not explain implementation mechanics that the diff already shows.

Use meaningful kebab-case branch names. If the branch relates to an issue, use `issueNumber-keywords-from-issue-title`.

Do not create, amend, or push commits unless the user explicitly authorizes that action.
